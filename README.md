# مخرِّب الرياض

لعبة استنتاج اجتماعي على شبكة الوايفاي المحلية. خريطتها أحياء الرياض، وطرقها الحقيقية هي الممرات.

## التشغيل

تحتاج جهاز فيه Node.js نسخة ١٨ أو أحدث، متصل بنفس الوايفاي مع الجوالات.

```
node server.js
```

بيطبع لك عنوان زي:

```
http://192.168.1.15:3000
```

كل واحد يفتح هذا العنوان بمتصفح جواله، يكتب اسمه، ويدخل. أول واحد يدخل يصير صاحب الغرفة وهو اللي يبدأ الجولة. تقدر تضيف بوتات تكمّل العدد إذا ما اكتمل الشباب.

ما فيه `npm install`. الويب سوكِت مكتوب من الصفر داخل `server.js` عشان يشتغل بأمر واحد.

## الملفات

| الملف | وش فيه |
|---|---|
| `server.js` | سيرفر HTTP + ويب سوكِت + منطق اللعبة كامل (السيرفر هو المرجع) |
| `public/shared.js` | الخريطة والثوابت ودوال المشي والرؤية والمسارات. يستخدمها السيرفر والمتصفح |
| `public/index.html` | الواجهة كاملة: الرسم، عصا التحكم، اللوبي، الاجتماع، المهام |
| `longtest.js` | اختبار طويل: عملاء ويب سوكِت حقيقيون يلعبون عشر جولات متتالية ضد السيرفر |
| `featuretest.js` | اختبار سيناريوهات: قطع الكهرب، مخروط الرؤية، إعادة الاتصال |

## اللعب

الشباب يفوزون إذا خلّصوا كل المهام أو طردوا المخرِّب بالتصويت. المخرِّب يفوز إذا صار عدد المخرّبين مثل عدد الباقين.

كل واحد يشوف مخروطًا باتجاه مشيه ودائرة صغيرة حوله، والجدران تحجب الرؤية. المهام على معالم حقيقية: برج المملكة، الفيصلية، البوليفارد، الطريف، قصر المصمك، سوق الملز، ومحطات بنزين وكوفيات.

المخرِّب عنده زر يقطع الكهرب ٢٥ ثانية: المهام تتوقف ورؤية الجميع تضيق. له كولداون مستقل عن كولداون الطيحة. الاجتماع يرجّع الكهرب.

إذا انقطع اتصال لاعب (أو سكّر الصفحة) ورجع خلال ٣٠ ثانية، يرجع لنفس مقعده ودوره ومهامه وموقعه. الباقون يشوفونه معلَّمًا "منقطع" لين يرجع. لو ما رجع يُطرد فعليًا.

## الأرقام المعايَرة

انضبطت على محاكاة ٤٠ جولة لكل إعداد، والنتيجة الشباب يفوزون ٥٧٪ بمتوسط جولة دقيقة ونص. كلها في `C` داخل `shared.js`:

- `KILL_CD` ٢٦ ثانية بين الطيحة والثانية
- `HUNT_LEAD` ٣ ثواني، البوت المخرِّب يقرّب من فريسته قبل جهوز الكولداون
- `ISO` ٣٠٠، ما يطيّح إلا إذا ما فيه أحد ثاني يشوف الضحية
- `WORK_MS` ٦ ثواني، وقت البوت على المهمة
- `VIS_CREW` ٣٠٠ و `VIS_IMP` ٤٢٠، مدى الرؤية

الأرقام المضافة بعدها لم تغيّر أيًا مما فوق، والبوتات لا تستخدم التخريب ولا تعتمد على الرؤية، فمعايرة الـ ٤٠ جولة (بوتات ضد بوتات) لم تتأثر:

- `SAB_MS` ٢٥ ثانية مدة الظلمة، `SAB_CD` ٤٠ ثانية كولداون، `SAB_FIRST` ٢٠ ثانية أول جهوز
- `SAB_VIS_CREW` ١٢٠ و `SAB_VIS_IMP` ٢٦٠ الرؤية وقت الظلمة
- `VIS_NEAR` ١١٠ نصف قطر الدائرة الصغيرة، `VIS_HALF` ١٫٢٥ راديان نصف زاوية المخروط
- `RECONNECT_MS` ٣٠ ثانية مهلة الرجوع

## الاختبارات

```
node longtest.js                 # عشر جولات كاملة، يطبع لكل جولة الفائز والمدة والمهام
ROUNDS=3 HUMANS=4 BOTS=3 node longtest.js
node featuretest.js              # سيناريوهات الميزات، ينتهي بكود 1 لو فشل تحقق
```

كلاهما يشغّل السيرفر بنفسه على منفذ حر ويتصل بعملاء ويب سوكِت حقيقيين (WebSocket المدمج في Node 22). لا اعتماديات.

## اللي تأكدت منه

- كل نقاط الخريطة موصولة، جربت المسار بين كل معلم وكل معلم، صفر فشل
- الجدران تحجب الرؤية فعليًا
- السيرفر يرفض القفزات البعيدة والمشي داخل الجدران وإنهاء المهام من بعيد
- المضيف وحده يقدر يبدأ الجولة
- السيرفر يصمد لما ينقطع لاعب فجأة
- فك إطارات الويب سوكِت اختُبر على الرسائل القصيرة والطويلة والملتصقة والناقصة
- عشر جولات متتالية بأربعة لاعبين حقيقيين وثلاثة بوتات تنتهي كلها صح، بدون أخطاء ولا انقطاع (`longtest.js`)
- قطع الكهرب: يُرفض قبل الكولداون وأثناء الظلمة، المهام تُرفض وقت الظلمة، الرؤية تضيق وترجع، كولداون الطيحة ما يتأثر
- مخروط الرؤية: اللي وراك خارج الدائرة الصغيرة ما يوصلك من السيرفر أصلًا
- إعادة الاتصال: نفس المعرّف والدور والمهام والموقع، السر الخاطئ مرفوض، التبويب الثاني يأخذ المقعد، وبعد المهلة يُطرد

## ملاحظات على السجل القديم

سكربت الاختبار القديم كان يموت بعد أول جولة. السيرفر نفسه يعبر بين الجولات بلا مشكلة (`again` ثم `start` عشر مرات). مصدرا التجمّد اللي ظهرا أثناء إعادة كتابة السكربت كانا في جهة العميل وفي طبيعة اللعبة، لا في السيرفر:

1. `S.findPath` يرجّع خلايا تلامس الجدران، والبوتات ما تتحقق من الجدران فما يفرق معها. لكن عميلًا يحترم `walkable` بنصف قطر ١٥ ما يقدر يوقف على ٢٣٪ من تلك الخلايا فيلتصق بالحافة. `longtest.js` يستخدم BFS يراعي نصف القطر.
2. لو الشباب الأحياء كلهم متجمّعون وما يخلّصون مهام، البوت المخرِّب ما يطيّح أبدًا بسبب قاعدة `ISO`، وما فيه حد أقصى لمدة الجولة. مع لاعبين حقيقيين ينحل بالمهام، لكنه احتمال جمود حقيقي بلا مؤقّت.

## اللي لسه مفتوح

- عدّاد المهام: البوت الشاب اللي خلّص مهامه الخمس يستمر يزيد `doneTasks` كل مرة يقف عند معلم، فالشريط يوصل ١٠٠٪ قبل ما يخلّص البشر مهامهم (ظهر في السجل `26/25`). تصحيحه يغيّر التوازن فيحتاج إعادة معايرة قبل تطبيقه
- ما فيه حد أقصى لمدة الجولة
- ما فيه دردشة نصية بالاجتماع
